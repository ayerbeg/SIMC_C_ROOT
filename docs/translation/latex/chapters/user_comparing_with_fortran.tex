\chapter{\texorpdfstring{Comparing SIMC++ with the Fortran SIMC (user guide)}{Comparing SIMC++ with the Fortran SIMC (user guide)}}\label{translation_report-useru5fcomparingu5fwithu5ffortran}
\simcabstract{Two kinds of comparison are possible:}
\begin{itemize}
\item \textbf{exact}: RANLUX + \code{-{}-{}fortran-{}compat}\simcidx{Command-line options!fortran-compat@\code{-{}-{}fortran-{}compat}} against a Fortran run of the same input. The files must be identical
(8.4\footnote{SIMC++ User Manual, ``8.4 Reproducing legacy SIMC results exactly'' (\code{docs/\allowbreak{}manual/\allowbreak{}markdown/\allowbreak{}user/\allowbreak{}08\_\allowbreak{}running\_\allowbreak{}and\_\allowbreak{}reproducibility.\allowbreak{}md})});
\item \textbf{statistical}: any SIMC++ run (default mode, mt64, any seed, any number of threads) against a Fortran run, with
\code{simc\_\allowbreak{}compare}. This guide covers it. The full description of the statistics is in \code{validation/\allowbreak{}README.\allowbreak{}md}.
\end{itemize}
\section*{\texorpdfstring{1. Building \code{simc\_\allowbreak{}compare}}{1. Building simc\_\allowbreak{}compare}}\addcontentsline{toc}{section}{\texorpdfstring{1. Building \code{simc\_\allowbreak{}compare}}{1. Building simc\_\allowbreak{}compare}}\label{translation_report-useru5fcomparingu5fwithu5ffortran:1-building-simcu5fcompare}
\code{simc\_\allowbreak{}compare} is a separate CMake project in \code{validation/} (user manual 2.3\footnote{SIMC++ User Manual, ``2.3 Building'' (\code{docs/\allowbreak{}manual/\allowbreak{}markdown/\allowbreak{}user/\allowbreak{}02\_\allowbreak{}installation.\allowbreak{}md})}):

\begin{simcshell}[basicstyle=\ttfamily\tiny]
cmake -S $SIMCPP_SRC/validation -B $SIMCPP_BUILD-validation -DCMAKE_PREFIX_PATH=$ROOTSYS -DCMAKE_BUILD_TYPE=Release
cmake --build $SIMCPP_BUILD-validation -j8
\end{simcshell}
\section*{\texorpdfstring{2. Running it}{2. Running it}}\addcontentsline{toc}{section}{\texorpdfstring{2. Running it}{2. Running it}}\label{translation_report-useru5fcomparingu5fwithu5ffortran:2-running-it}
\begin{simcplain}[basicstyle=\ttfamily\scriptsize]
simc_compare --a SPEC --b SPEC --out DIR [--config CFG.json] [--label-a NAME] [--label-b NAME]
             [--skip v1,v2] [--nbins N] [--prefer-hist] [--no-pdf] [--expect PASS|FAIL|IDENTICAL]
             [--mode-a compat|corrected] [--mode-b compat|corrected]
\end{simcplain}
A \code{SPEC} is a SIMC++ \code{<run>\allowbreak{}.\allowbreak{}summary.\allowbreak{}json}, a Fortran \code{<run>\allowbreak{}.\allowbreak{}hist} (the tool reads \code{.\allowbreak{}hist}, \code{.\allowbreak{}geni} and \code{.\allowbreak{}root} next to
it), a \code{<run>\allowbreak{}.\allowbreak{}root}, or a directory with one run. Example: a full SIMC++ run of \code{eep\_\allowbreak{}h\_\allowbreak{}elastic\_\allowbreak{}rad\_\allowbreak{}A} (default mode,
seed 4242, 4 threads) against the Fortran reference run (seed 12345):

\begin{simcshell}[basicstyle=\ttfamily\tiny]
simc++ $SIMC_FORTRAN/infiles/eep_h_elastic_rad_A.inp -o l2 --seed 4242 --threads 4 > l2.log
$SIMCPP_BUILD-validation/simc_compare --a $SIMC_REFERENCE/runs/eep_h_elastic_rad_A --b l2/eep_h_elastic_rad_A.summary.json --out cmp \
                       --config $SIMCPP_SRC/validation/config/compare_default.json
\end{simcshell}
It writes \code{cmp/\allowbreak{}summary.\allowbreak{}txt}, \code{cmp/\allowbreak{}summary.\allowbreak{}json}, \code{cmp/\allowbreak{}compare.\allowbreak{}pdf} (one page per variable: weighted and unweighted
overlays with B/A ratios) and the two parsed run summaries. The exit status is 0 for PASS (or when \code{-{}-{}expect} is met),
1 for FAIL, 2 for a usage or I/O error.

\section*{\texorpdfstring{3. Reading the verdict}{3. Reading the verdict}}\addcontentsline{toc}{section}{\texorpdfstring{3. Reading the verdict}{3. Reading the verdict}}\label{translation_report-useru5fcomparingu5fwithu5ffortran:3-reading-the-verdict}
The top of \code{summary.\allowbreak{}txt} from the example:

hsdelta    compared        -7.005        7.05        0.17       0.147        0.15       0.266  ok
...
\end{simcplain}
\begin{itemize}
\item \textbf{Run-level tests}: the acceptance Ncontribute/\allowbreak{}Ntried (binomial), the weighted yield per try, \code{wtcontr},
\code{AVERAGE.\allowbreak{}sigcc} (pulls), the deterministic quantities (\code{sigcc\_\allowbreak{}central}, charge, \code{targetfac}, luminosity, \code{genvol},
\code{Ngen}, which must agree to the print precision; a mismatch is a \textbf{gross failure}), and every stop counter
(binomial per counter, plus a χ² of each spectrometer's partition of its trials).
\item \textbf{Tree variables}: for each branch, four tests on weighted histograms and the unbinned weighted KS test. Events with
NaN/Inf values are counted and excluded.
\item \textbf{Verdict}: with N tests at α = 0.01 about N·α failures are expected by chance. \textbf{PASS} if the number of failures F is
compatible with that (binomial tail probability ≥ 0.001) \textbf{and} there is no gross failure (no deterministic
mismatch, no p < 1e-5). Otherwise FAIL. A handful of failures with p around 0.001-0.01 is normal; a single gross
failure is not.
\end{itemize}
Configuration (\code{validation/\allowbreak{}config/\allowbreak{}compare\_\allowbreak{}default.\allowbreak{}json}, all keys optional): \code{alpha}, \code{global\_\allowbreak{}alpha}, \code{gross\_\allowbreak{}p},
\code{nbins}, per-variable binning, \code{variables}, \code{skip}, the normalisation of each side (\code{norm\_\allowbreak{}a}/\code{norm\_\allowbreak{}b}: per try,
normfac or a number), \code{det\_\allowbreak{}rel\_\allowbreak{}tol}.

Comparing two runs of the \textbf{same} code with the same seed must give \code{IDENTICAL} (\code{-{}-{}expect\ IDENTICAL}).

\section*{\texorpdfstring{4. Mode of each side: \code{wtcontr}}{4. Mode of each side: wtcontr}}\addcontentsline{toc}{section}{\texorpdfstring{4. Mode of each side: \code{wtcontr}}{4. Mode of each side: wtcontr}}\label{translation_report-useru5fcomparingu5fwithu5ffortran:4-mode-of-each-side-wtcontr}
The σ of \code{wtcontr} uses the events of the pass\_cuts window of each run. That window differs between the Fortran and the
corrected mode (D-006). The tool takes the mode of a SIMC++ JSON from its \code{run.\allowbreak{}fortran\_\allowbreak{}compat}; a Fortran \code{.\allowbreak{}hist} counts as
compat. For a summary without that key, pass \code{-{}-{}mode-{}a/\allowbreak{}-{}-{}mode-{}b\ compat|\allowbreak{}corrected}. A warning appears when the window does
not reproduce the run's own wtcontr within 0.2 \% (usually a wrong mode).

For each failure, check the variable against \hyperref[translation_report-useru5fdifferences]{the list of differences}. If it is not listed there,
look further: run the corrected and the compat SIMC++ runs with the same seed, which differ only by the corrections,\allowbreak{} or

is a RANLUX run: if it is identical to the Fortran, the flag was a fluctuation.
